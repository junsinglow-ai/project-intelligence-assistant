## Intentional messiness

Every row was recorded as the file was written, so this table describes what the data actually contains. The handling column is the pipeline's contract: if a behaviour is not implemented yet, say so rather than deleting the row.

**Status: implemented.** `make ingest` applies the handling described below and reports the flaw
classes it acted on; `backend/tests/test_cleaning.py` and `test_ingestion.py` assert each one against
these files, naming the flaw ID in the test. The normalisation lives in
`backend/app/ingestion/cleaning.py`, shared by the PDF and tabular loaders.

Two flaws are handled in a way worth noting, because the obvious reading is wrong:

- **F06** cannot be resolved per value. `1.0931` is a 109% overspend in a ratio-scaled column and
  1.09% in a percent-scaled one, so the scale is decided once per column from its other values.
- **F09** in the risk register is not only line endings: one row has 14 fields against a 13-column
  header, because an unquoted comma inside the description splits it. The row is repaired by testing
  each adjacent rejoin, not discarded.

One flaw is **not** in the table below, because it is an extraction artifact rather than something
written into the source: the bullet glyph in the status-report PDFs extracts as a literal
`(cid:127)`, and is stripped during cleaning.

## Regenerating

```bash
uv run render_dataset.py <spec>.json --out <dir> --seed 11
```

Pass `--flaws none` for a clean control copy of the same dataset, which is useful for isolating whether a pipeline problem comes from the data or from the code.
